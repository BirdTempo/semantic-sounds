# Sub-project 2: the sound review tool

Status: approved for planning
Date: 2026-09-19
Author: Andrew Carmer (BirdTempo), with Claude Opus 5

## 1. Goal

Build a local tool that lets a human review the curated sound set by
ear, reject the sounds that do not work, and get new candidates for
each rejection without leaving the tool.

The tool mirrors the icon project's review tool
(`semantic-icons/scripts/review/`, spec
`docs/superpowers/specs/2026-09-15-icon-review-design.md`). Sounds
replace icons, a play button replaces a rendered image, and a patch
replaces an SVG. Everything else keeps the same shape, for the same
reasons.

## 2. Scope

In scope:

- Screen 1: review every sound in the set, mark yes or no, give a
  reason for a no.
- Screen 2: for each rejected sound, three new candidates, generated by
  `claude-opus-5`, streamed in as they arrive, auditioned by ear, and
  accepted back into the set.
- An append-only record of every rejection, which becomes context for
  the next generation of that phrase.
- A fake generator, so tests and manual work cost nothing.

Out of scope (later sub-projects):

- The public generation endpoint that end users hit for a miss
  (sub-project 5). This tool calls Claude directly, for the author
  only. The two are separate systems.
- The full 300-500 sound set (sub-project 3). The tool must scale to
  that size, but this sub-project reviews the 40-sound seed set.
- Any hosted or multi-user deployment. This tool binds to 127.0.0.1
  and has no authentication, by design.

## 3. Decisions

- **Include the redraw loop now.** A review tool that can only say "no"
  leaves every rejection unaddressed. The icon project built both
  screens together for the same reason.
- **`claude-opus-5` for generation.** The top-level brief names it.
  Quality matters more than cost here, because a human judges every
  candidate anyway.
- **Three candidates per rejection.** Same as icons. Enough variety to
  escape a bad idea, few enough to audition quickly.
- **No framework, no build step for the pages.** Plain `node:http`,
  plain HTML/CSS/JS read fresh from disk on every request. The icon
  project's reasoning holds: a review tool that needs a restart to show
  an edit slows the work it exists to speed up.
- **One renderer, still.** The pages must not reimplement synthesis.
  The server bundles `src/library/index.ts` with esbuild at startup and
  serves it to the pages as an ES module, so the browser plays exactly
  what the validator measured.

## 4. Screens

### Screen 1: library review (`GET /`)

A list of every sound: phrase, category, concept, a play button, and a
Yes/No radio defaulted to Yes. A No reveals an optional reason field.

- The tool keeps no memory of past approvals. Every session starts with
  everything marked Yes. A reviewer's job is to find what is wrong now,
  not to re-confirm what was right before.
- Choices persist in `localStorage`, inside try/catch. The page works
  without it; a reload just loses the marks.
- Rows render in pages of 60 with an `IntersectionObserver` sentinel.
  40 sounds do not need this; 500 will.
- A fixed bottom bar shows "N marked no" and a button reading
  "Redraw N sounds (3N generations)". The multiplication is written out
  because the reviewer is spending money by pressing it.

### Screen 2: redraw (`GET /redraw`)

One row per phrase awaiting a redraw. Each row shows the current sound
and three candidate slots (A, B, C), each with its own play button.

- Slots arrive over Server-Sent Events (`GET /api/events`, event type
  `slot`, matched to a slot by `id`). A pending slot shows a spinner; a
  failed slot shows its reason.
- Choice per row: A, B, C, "None, redraw" (default), or "Keep current".
- Submit acts only on rows with no pending slot. Rows still in flight
  keep their choice across a submit.
- "None, redraw" records all three candidates as rejections and starts
  another round for that phrase.
- Accepting a candidate writes it into the set (section 6).

## 5. Generation

`draw.ts` generates one slot:

1. Build the prompt (`prompt.ts`, pure).
2. Call Claude (`anthropic.ts`) with a structured output schema for
   `{concept, patch}` — concept first, so the model states its intent
   before it synthesizes, the same ordering the icon project found
   improved quality.
3. Check the result with `checkEntry` from `src/library/validate.ts`.
   The contract that governs the shipped set governs generated
   candidates too; there is no second, looser standard.
4. On a problem, retry once with the exact problem list. On a second
   failure, fail the slot and report why.

The prompt:

- **System:** `docs/sound-style-guide.md` in full, a job statement, and
  the output contract. Cached (ephemeral), because it repeats across
  every slot of every round.
- **User:** up to 8 reference sounds from the same category (phrase,
  keywords, concept — not their patches, which would bloat the prompt
  and invite copying), the target phrase and category and its first 10
  keywords, up to 9 previously rejected patches for this phrase
  (newest first, each with its reason or "no reason given"), and a slot
  hint.
- **The current concept is withheld.** A rejected sound's concept is
  the idea the reviewer turned down; showing it anchors the model to
  the thing that failed.
- **Slot hints:** A — the most literal reading of the phrase. B — a
  different sonic approach: a different primary waveform or layer
  structure (a noise-led sound where A was tone-led, or the reverse).
  C — simpler: fewer layers, less movement.

`queue.ts` caps generation at 6 at once.

`fake.ts` (`REVIEW_FAKE_DRAW=1`) returns a valid patch after 0.5-3s and
fails about one in six, to exercise the failure paths. No test calls
the real API.

## 6. Storage

### The set itself

An accepted candidate replaces the entry with that `name` in whichever
`src/library/sounds/*.json` file holds it:

- `checkEntry` runs before any write. A failing entry writes nothing
  and returns 409 with its problems.
- The write is atomic: a `${path}.${pid}.tmp` file, then a rename.
- The file's existing trailing-newline convention is preserved. The
  icon project learned this the hard way: without it, a one-entry
  change shows as a whole-file diff.
- `src/library/sounds/generated.ts` is rebuilt after a successful
  write, so the shipped bundle and the JSON sources never drift.

### `scripts/review/rejected.jsonl` (committed)

Append-only. One JSON object per line:

```
id, name, phrase, category, concept, patch, reason,
origin ("library" | "generated"), model (string | null),
round (number), rejectedAt (ISO 8601)
```

Lines are only ever appended, never edited or removed. This file is the
memory that stops the next attempt from repeating a rejected idea, and
it is worth keeping in git for exactly that reason.

### `scripts/review/session.json` (gitignored)

In-flight redraw rounds. Each item has exactly three slots, each
`pending`, `ready`, or `failed`. On startup, any slot left `pending`
becomes `failed` with "the server stopped before this sound arrived".
Work in flight must heal itself after a crash rather than hang.

## 7. Architecture

```
scripts/review/
  server.ts      node:http routing and the SSE stream
  store.ts       file I/O only: the set, rejected.jsonl, session.json
  session.ts     pure state machine (reject, decide, view, idle)
  prompt.ts      pure prompt construction
  anthropic.ts   the Claude call and its output schema
  draw.ts        generate, validate, retry once, fail
  queue.ts       concurrency cap
  fake.ts        the fake generator
  bundle.ts      esbuild the library for the pages
  tsconfig.json  typechecked as its own unit
  page/          library.html, redraw.html, review.css,
                 common.js, library.js, redraw.js
  *.test.ts
```

Routes:

| Route | Purpose |
|---|---|
| `GET /` | Screen 1 |
| `GET /redraw` | Screen 2 |
| `GET /api/library` | every entry, with its patch, for local playback |
| `GET /api/session` | the current redraw session |
| `POST /api/reject` | record rejections, start a round |
| `POST /api/decide` | apply per-row decisions |
| `GET /api/events` | SSE slot updates |

Concurrency safety comes from Node being single-threaded: every
mutation happens inside one synchronous function call, so two requests
cannot interleave writes to the three on-disk stores. Only the async
library rebuild is serialized explicitly.

`session.ts` validates a whole request body before making any write —
all or nothing — and throws a typed `ReviewError(status, message)` for
400, 409, and 503 outcomes.

Startup: verify `src/library/sounds` exists (the tool must run from the
repo root), recover stale `pending` slots, bundle the library, read
`ANTHROPIC_API_KEY` (absent and not in fake mode: fail immediately with
a clear message, rather than at the first redraw), bind `127.0.0.1`,
default port 5179, `--port` to override.

## 8. A small refactor this needs

`scripts/build-library.mjs` becomes `scripts/build-library.ts`,
exporting `buildLibrary()` with a CLI guard, the same shape
`scripts/prose-probe.ts` already uses. The server needs to rebuild the
bundle after accepting a candidate, and duplicating that logic would
let the two copies drift.

## 9. Testing

Vitest, with `scripts/**/*.test.ts` added to the existing include. No
test calls the real API; `draw`, `session`, and `server` tests inject
fakes.

- **store:** finds an entry across batch files; replaces it atomically;
  preserves each file's trailing-newline convention; refuses an entry
  that fails `checkEntry`.
- **session:** each transition; all-or-nothing body validation; the
  typed error codes; stale-pending recovery on startup.
- **prompt:** includes the style guide; withholds the current concept;
  orders rejected history newest first and caps it at 9; varies the
  slot hint by slot.
- **draw:** retries once with the problem list when a patch fails the
  contract; fails the slot after a second failure; never writes on
  failure.
- **server:** each route; the SSE stream emits a slot event; a bad body
  returns 400 and writes nothing.

## 10. Follow-ups to record

- The tool reviews by ear, one sound at a time. If reviewing 500 sounds
  proves slow, consider a "play all in category" sweep — but only with
  evidence from real use.
- Model choice is fixed at `claude-opus-5`. The icon project found Opus
  and Sonnet mixed on quality; if cost becomes a problem here, generate
  A with Opus and B/C with Sonnet, and let the ear decide.
